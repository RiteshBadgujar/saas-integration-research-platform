Identified Error Patterns
⚠️ Over-Conservative Limitation Classification (Heuristic Bleed)
Frequency: 4 apps Affected: Attio, Resend, Deel, Supabase Class: False Negative (Buildable)
The automated classifier's text parser flagged descriptive sentences starting with "None; ..." as blocker strings, inappropriately downgrading 4 truly friction-free APIs from "Buildable" to "Buildable with limitations". Fix: Strip leading "None;" clauses before evaluating limitation strings in buildability_classifier.py.
ℹ️ Single-User Token vs Multi-Tenant App Credentials
Frequency: 2 apps Affected: Jira, Notion Class: Schema Gap
Platforms offering both internal integration tokens and public multi-tenant OAuth require distinguishing developer testing ease from end-user authorization complexity. Fix: Add separate schema fields for single-workspace vs multi-tenant feasibility.
ℹ️ Silent Webhook Absence / Polling Dependency
Frequency: 1 app Affected: Notion Class: Assumption Error
Major modern platforms do not always expose event webhooks. Fix: Classify all polling-dependent architectures as "Buildable with limitations" and add a polling_required boolean field.

Section 11
Research Methodology & Limitations
How this research was conducted, what sources were used, and where the analysis has known limitations.
🌱
M1: Seed Dataset
100 apps selected across 10 categories. Official website and developer doc URLs verified for liveness. Composio toolkit catalog cross-referenced manually.
🤖
M2: Automated Research Engine
Multi-dimensional extractor: source_collector.py, auth_analyzer.py, buildability_classifier.py. 5-verdict decision engine with heuristic rules against verified_facts.py.
🗄️
M3: Full Dataset Generation
Executed researcher.py across all 100 apps. Pristine baseline locked in verification/automated_raw_output.json before any corrections.
🔍
M4: Manual Audit
30-app stratified sample (3 per category) verified against official developer documentation. Automated vs verified comparison recorded in verification_results.csv.
📊
M5: Analysis & Insights
reports/analyzer.py computed all statistics from corrected data/apps.json. All figures validated to sum correctly — 0 validation errors.
⚠️
Known Limitations
MCP status and rate limits may change rapidly. Only 30/100 apps were manually verified. Partner-gated API terms evolve with vendor relationships. Schema does not distinguish single-workspace from multi-tenant buildability.
Research Pipeline Architecture
data/seed_apps.json (100 apps, verified URLs)
→ research/verified_facts.py (ground-truth facts database)
→ research/researcher.py (master orchestrator)
→ research/auth_analyzer.py + buildability_classifier.py
→ data/apps.json + data/apps.csv (baseline locked)
→ verification/verifier.py (30-app manual audit)
→ verification/verification_results.csv + accuracy_report.json
→ reports/analyzer.py (M5 analysis)
→ reports/category_analysis.json + research_summary.json
